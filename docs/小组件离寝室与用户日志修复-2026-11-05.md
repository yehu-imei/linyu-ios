# 小组件离寝室使用与用户更新日志

## 设备选择与同步

- Android 依据上次设备及订单台账显示小组件，正在用水不受寝室筛选隐藏；不依赖附近扫描成功。
- iOS 原先优先读取小组件独立设置中的旧设备 ID；旧 ID 无效时直接显示“请先选择设备”，没有回落到 App 上次设备。
- 现在开始用水后各设置跟随上次设备，保留各自所在页面；当前使用中的上次设备优先展示。旧选择失效时回落到合法上次设备或唯一进行中的订单。
- 快照直接纳入当前订单的设备资料，并在订单切换时立即写入和请求刷新，不等待扫描或节流事件。
- 展示回落不改变旧按钮的目标校验；关闭仍需原账户、设备、订单号和开始时间匹配。空闲设备仍遵守寝室筛选。
- 系统是否实际及时展示新时间线仍需 SideStore 安装后验证，不能以单元测试或构建成功代替实机验证。

## 用户更新日志

- `docs/APP_CHANGELOG.md` 是专用精简文档。核对 Android CHANGELOG 和公开 Release 后，收录 14 个已发布历史版本，另记待发布 3.1.1（不展示）。每版至多五条。
- 两端读同一文档格式，按明确平台标签区分内容，不再根据“新增/功能/修复”标题关键词截断 Release 正文。
- 两端仓库各保留一致的内置副本，默认展示三个版本，展开后可查看全部；远程失败仍能看内置/缓存内容。
- 远程规范来源：`https://raw.githubusercontent.com/yehu-imei/linyu/master/docs/APP_CHANGELOG.md`。Android 本次改动保持本地，文档尚未发布到该分支时自动使用内置副本；发布文档后，无需改客户端地址。
- GitHub Release 仍用于判断是否有新版及 Android APK 下载，不用日志中的版本号推断可下载版本；iOS 自签教程不变。

## 验证重点

1. 不在寝室、附近为空：App 开始上次云端设备，桌面应显示相同设备的使用状态及计时；结束后仍保留该设备和消费。
2. 旧小组件曾选其他设备/地址：App 新开水后跟随实际设备，关闭入口不得串台。
3. 无网打开应用信息：可见简短版本日志，检查更新失败不能清空它。
4. 日志中“优化/兼容”等普通条目不丢失，Android 专属后台监控或单格组件不展示给 iOS。
