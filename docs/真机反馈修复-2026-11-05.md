# 真机反馈修复（2026-11-05）

## 证据与边界

检查 `linyu-log-20261105-083513.txt`：三次云端开阀成功，成功后一瞬间没有相应关闭/订单结束记录。旧日志不记录使用页显隐原因，不能仅据此断言唯一闪回原因。本轮将使用页显隐状态移到水控对象，订单切换直接驱动显示，并记录显隐原因及源码提交，继续真机验证。

## 对应修改

1. 使用页与订单同生命周期；不再由容易复位的视图局部布尔值单独管理。
2. 组件订阅改为节流，防止连续广播使防抖永远等不到执行；扫描结束、开关结束、账单加载和结算变化主动刷新。普通数据变更最多合并两秒再请求系统刷新，同账号保留冷启动展示缓存。
3. 中型组件直接使用 Link；小型组件因多点击区域限制保留 AppIntent，但只投递路由，不再 UIApplication.open 自己。普通导航在唤起阶段即可消费，水控仍等待活跃场景。
4. 移除 tools/fix_icon_corners.py，已修好的图标资源保留；不重写 Git 历史。
5. Toast 放到应用弹窗上层；按每次消息重置 2.5 秒计时，移除恢复已有订单、普通刷新、历史对账完成等额外提示。开关失败、未确认关闭、当前结算等重要信息保留。
6. 扫码页显式观察授权状态：未授权说明、拒绝后的“去设置”、受限说明；从设置返回后重建相机。相册选图仍可使用。
7. 组件随机身份改为会话级，普通刷新或另一设备变化不作废上次设备。开启入口遇到本地已有订单只恢复，不重复创建；关闭仍校验账号、SN、订单号及开始时间。云端表不要求扫描，BLE 表仍要求靠近并扫描。
8. 与 Android SpendingAnalytics 对比：本月 1 日到今天，空日补零，不含未来日期，均值按笔数；保持现有计算，增加边界回归。
9. 退出确认的紧凑卡片最大宽度 290，其他弹窗不变。

## 真机复测

- 冷启动及保留后台分别从组件账单/设备入口进入，再在 App 开水，使用页不能闪回。
- 退出 App 后确认状态/账单/附近设备刷新；系统收到刷新请求不保证立即重绘。
- 上次设备长时间后开水；使用中再次点旧开启入口只能恢复，旧关闭入口不得关闭新订单。
- 拒绝相机权限后有说明和设置入口，授权返回可扫码。
- 本轮不调用真实水控 API；编译、离线测试不等于真机阀门验证。
