# 小组件入口与日志刷新修复

## 真机证据

- 本次日志中，12:51:43 收到小组件停止入口，12:51:58 手动关闭完成后才开始处理组件请求
- 这说明 URL 已送达，不能只归因于扩展或设备离线；主界面的请求调度也存在问题
- 12:54:32 记录“用户更新日志暂未刷新，保留本地内容”，确认手机此次下载失败
- 日志截取从设备已开启后开始，没有覆盖用户描述的完整闪回瞬间，不声称已在真机复现或验证修复

## 改动

- 安装教程按钮改为“安装教程”，链接补齐 `.ipa的安装.md`
- 小组件导航与水控入口统一使用 Link，通过 onOpenURL 交付，不保留小尺寸组件的空扩展执行路径
- 主界面使用 UIApplication 当前激活状态执行请求，增加 didBecomeActive 兜底，不依赖异步回调捕获的旧 scenePhase
- 普通导航立即消费；开关入口可替换待处理的普通导航，普通导航不能覆盖待执行的开关
- 同次前台会话的重复导航不再执行；重新进入后台后允许用户再次点击同一入口
- 异步刷新完成后不再强制返回首页；开启成功仅打开对应设备的使用页
- 日志刷新独立于版本检测，每次进入卡片和回前台均可触发；相邻请求合并，失败可再次重试
- 原始文件下载失败时通过 GitHub API 获取同一文档；有效新文档整体替换缓存，失败保留本地内容
- 请求跳过本机 HTTP 缓存，并记录成功缓存的版本数与文档字节数

## 对照与边界

- Android MainActivity 的导航请求消费一次后清空，不在网络刷新完成后再次导航
- Android 小组件的开关携带明确目标，iOS 仍复用原有云端/BLE 控制及订单身份校验，不绕过这些校验
- Apple 场景链接文档：https://developer.apple.com/documentation/widgetkit/linking-to-specific-app-scenes-from-your-widget-or-live-activity
- 日志唯一远程来源仍为安卓仓库 `master/docs/APP_CHANGELOG.md`；修改 iOS 仓库的副本不会改变远程读取地址
- 没有访问真实开关水接口；版本保持 3.1.0 (18)

## 真机复测

1. 安装后打开 App 一次，让系统替换旧组件时间线
2. 冷启动和热启动分别点 2×2/2×4 的开启与停止，确认自动执行对应设备动作
3. 从小组件普通区域进入 App，再在 App 内点击使用，确认不再闪回首页
4. 开启后不返回桌面，确认没有延迟的旧导航或旧开关动作
5. 更新远程文档后重新进入应用信息；下载成功记录版本数和字节数，断网时仍显示缓存
